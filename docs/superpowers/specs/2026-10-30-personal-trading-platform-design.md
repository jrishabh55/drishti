# Private personal trading platform

User authorization: after the feature audit, the user explicitly requested all nine remaining areas, using Codex and Claude Code in parallel. Build on the existing product and deploy without activating live orders. Scope is the user and sister, not a public service. Existing provider terms remain separate from product authorization; do not invent license checkboxes or public-launch work.

## Outcome
A stock can move from research or scanner selection into a saved, versioned strategy, a selected paper portfolio, a historically tested experiment, automatic paper execution and attributable performance. The same strategy may later run in confirmed or explicitly opted-in automatic live mode using the owner's broker connection. Telegram provides authenticated supervision. Everything remains usable with unavailable credentials through honest connection/data states and controlled-provider tests.

## Architecture and approach
Extend current FastAPI/TanStack modules and their pure evaluation, risk and paper functions. Retain upstream tradingagents/ and cli/ unchanged. Keep one order authority and existing ownership/daily-arm/kill/reconciliation gates. Prefer a shared deterministic strategy evaluator for runtime and historical testing. Kite candles and scanner caches must be scoped to the selected direct-grant connection owner; never write them to global Yahoo caches. Preserve the current public-feed path for unconnected users and label fallback accurately. Do not replace the application or add an unrelated workflow engine.

Alternatives considered: a new autonomous agent orchestrator would duplicate risk/order state; independent code for backtests would drift from real strategy rules. Use the existing product with common strategy semantics and private data adapters instead. Defaults and bounds below are coordinator implementation decisions, not claims of user-selected parameters.

## Shared contracts
- Strategy retains legacy fields/defaults and adds portfolio_id (default: default), interval (1m or 5m, default5m), scanner_id (optional owned/prebuilt scanner), min_volume_x (optional), exit policy, and mode off|paper|confirm|auto. Paper supports named portfolios. Broker confirm/auto require Default; paper capital cannot authorize real orders.
- Modes are Off by default. Existing live order environment gate remains0 in deployment; no worker arms, enables, connects an account, sends a message, incurs paid analysis or places a real order.
- Attribution fields are strategy_id, strategy_name, strategy_version. Stamp these from an owned strategy onto generated plans, tickets, order payloads, paper/live trades and backtests. Legacy records without attribution display Manual/legacy, never inferred ownership.
- A strategy edit increments its version. An in-flight scan cannot act using an old version or undo a pause/kill. A ticket/trade remains bound to its creation portfolio and strategy version after subsequent edits.
- Exit policy uses optional breakeven_after_r, trail_after_r, trail_distance_r, scale_out_at_r and scale_out_pct. Values are finite and positive; scale_out_pct is >0 and <100. Absent policy preserves existing full-position fixed-stop/target semantics. Completed candles only, conservative ambiguous-bar ordering, no past-bar fills for new orders.
- Historical strategy tests are distinct from Time Machine Monte Carlo and AI analysis batches. Backtest body includes strategy_id, start_date, end_date, optional split_date and bounded symbol selection. Use<=20 symbols and<=60 calendar days initially, reject inverted/future dates, identify incomplete sessions and insufficient history. Save immutable strategy/config/source snapshots with results, costs, trades and train/test split labels. No fabricated scores or automatic paid AI runs.
- Runtime diagnostics record last_scan time/source and per-symbol outcomes (waiting, stale, no_data, blocked, paper, await_confirm, sent, limit_reached), separate from the bounded trade-signal list. Delayed data must never silently become a fresh live signal.
- Risk/sizing policy remains portfolio/account authoritative. All money and ownership checks are server-side; source sharing never shares broker credentials, order authority or private trading books.

## Deliverables
1. App-wide scoped Kite market data: both general scanner engine and ORB use selected own/shared connection when ready. Support the217FNO and500 universes within provider limits; replace app's200-symbol cap with a documented safe provider-supported bound. History bootstrap is background/bounded and rate-limited. Quotes, source coverage, backfill progress and stale fallback are visible. Candle conditions use completed candles; prices/fundamentals/closed daily history are distinguished truthfully.
2. Portfolio strategies: selection, attribution,1m/5m/volume rules, scanner-driven symbol candidates and advanced exits above. Automatic Paper mode already exists and must be extended, not duplicated. Complete freshness/skip diagnostics and pause controls.
3. Saved strategy backtests and UI: replay identical entry/exit/risk semantics, no future data, costs/slippage, data coverage, version snapshots, split-period reporting and comparisons. Never present profitable test output as a prediction.
4. Analytics: strategy/version and portfolio filters, cross-portfolio paper overview, separate paper/live outcomes, realized and fresh marked open P&L, equity/drawdown, available benchmark comparison, journal annotations and CSV export. Existing fees are estimates unless reconciled to actual broker charges; label that clearly. Do not add paper equity to real equity as money earned.
5. Research-to-strategy guided flow: from analysis levels or scanner results create an editable OFF strategy draft, explicit symbol/timeframe/risk/portfolio review, then user-controlled Paper enable. Keep paid model calls deliberate. Add the flow to the Guide.
6. Operational readiness: daily connection/session/feed/loop/strategy state, skipped/blocked causes and recovery visible. Meaningful restart/revoke/stale/duplicate/cross-user regressions. Real full-session trial requires user connection and an actual trading session; report this external validation dependency without substituting simulated evidence.
7. Opt-in unattended live mode: preserve every existing broker gate, daily arm, identity binding, live-data freshness and account risk checks. Require a separate explicit strategy auto opt-in; auto mode creation alone cannot send orders. Kill/disarm/edit wins over running scan. Default deployment remains disabled.
8. Mobile supervision: verified Telegram strategy status, performance and pause/resume with explicit identity/ownership and confirmation; resume never arms live trading. Daily summaries deduplicated across restarts. Extend live approval only behind distinct opt-in and the existing exact-ticket broker gates, or route a live approval card to the app's existing exact-ticket typed confirmation when the channel cannot meet them. Paper approval behavior preserved. No messages sent during validation.
9. Reviewed deployment and usage: scoped independent reviews plus broad integrated review, full backend/frontend/typecheck/build, preserve data/encryption/media volumes, deploy existing Dokploy app with live orders0, authenticated browser QA. Document setup and the remaining user-login/full-session validation step.

## Non-goals
Public launch, exchange derivatives/short selling, delivery/swing broker automation and multi-broker execution are not included. No real financial action is authorized by this implementation task. No guarantee that a provider never drops data or that any strategy makes money.
